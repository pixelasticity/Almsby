# Almsby Visual Language

Defines the visual point of view agents should preserve when designing or changing Almsby interfaces.

## Core principle

Do not optimize for generic visual attractiveness. Optimize for a recognizable Almsby experience that makes the user's next step obvious, preserves understanding and control, and gives physical products and their makers appropriate dignity.

## Agent use

Agents should read relevant visual-language documents before proposing a visual direction, prefer proven patterns, use references as evidence rather than templates, explain material departures, and inspect rendered output before judging quality.

Agents should not rely on vague terms such as "modern", "premium", or "beautiful" as design rationale, nor default to cards, pills, gradients, dashboard grids, or decorative UI.

## Pattern status

- **Approved** — explicitly accepted as part of Almsby's visual language.
- **Proven** — successfully used in a real Almsby surface and supported by review/evidence.
- **Experimental** — proposed but not yet established.
- **Deprecated** — previously used but no longer preferred.
- **Rejected** — evaluated and intentionally not adopted.

Status is evidence-based, not determined by agent preference.
