# Interaction Patterns

Patterns are reusable interaction solutions, not rigid page templates.

A pattern belongs here when the same UX problem is likely to recur across Almsby.

## Pattern format

Each pattern should describe:

- Problem
- When to use
- When not to use
- User intent
- Interaction model
- Information hierarchy
- States
- Failure/recovery behavior
- Accessibility considerations
- Responsive considerations
- Examples in Almsby
- Related product decisions

## Initial pattern set

The following patterns are high-value candidates for Almsby's current product:

- Guided product creation
- Progressive disclosure
- AI-assisted drafting with approval
- Validation with actionable errors
- Draft / published state
- Coming-soon public state
- Compliance explanation
- Confirmation for consequential actions
- Empty states with a clear next action
- Processing / asynchronous work
- Recovery from failed automation
- Import and review
- Preview before publish
- Success with a useful next step

Do not create a pattern merely because a component exists. A pattern should solve a recurring user problem.
