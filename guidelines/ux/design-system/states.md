# Interaction States

Components and workflows should make meaningful state changes visible.

Relevant states may include:

- default
- hover
- focus
- active
- disabled
- loading
- processing
- success
- warning
- error
- empty
- draft
- published
- unavailable

States should communicate what happened and what the user can do next.

A visually polished default state is not sufficient if loading, error, empty, or disabled states are confusing.
