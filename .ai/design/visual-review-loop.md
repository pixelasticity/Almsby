# Visual Review Loop

For material UI work:

direction → implementation → rendered browser evidence → visual/UX critique → concrete design deltas → implementation → re-render.

A critique must identify the exact element, observed condition, consequence, severity, concrete corrective action, and evidence reference.

Avoid "make it nicer", "feels off", generic praise, arbitrary taste, or unrelated redesign.

Stop when required evidence exists, no critical visual/UX issue remains, remaining issues are explicitly accepted/deferred, and the completion requirements are satisfied.
