# Design Intelligence

Before creating a visual direction, consume the Product Constitution, applicable Product Decisions, relevant UX guidance, visual language, design-system constraints, proven references/baselines, and current UI when modifying an existing surface.

A direction must state the user/job, intended emotional outcome, primary hierarchy, composition, density, typography, imagery where applicable, interaction/state strategy, responsive implications, reused patterns, new patterns, and rationale.

"Modern", "premium", "clean", and similar adjectives are not sufficient rationale.

Prefer reuse and refinement. New visual patterns require a concrete problem statement, explanation of why existing patterns are insufficient, expected benefit, risks, and experimental status until reviewed.

No visual quality conclusion should be made from source code alone when rendered output is available.
